# 프론트엔드·백엔드 코드 점검 보고서

- 점검일: 2026-10-20
- 범위: `frontend/` Vue 화면 및 API 연결, `app/` FastAPI·SQLite 백엔드, 개발 환경 설정
- 방식: 프론트엔드와 백엔드를 분리해 코드 검토하고 연결부를 대조함
- 테스트: 실행하지 않음 (프로젝트 지침에 따라 생략)
- 코드 수정: 하지 않음. 요청대로 수정 권고를 이 문서에 취합함

## 요약

가장 먼저 확인할 문제는 FastAPI의 SQLite 연결이 스레드 간에 닫힐 때 발생할 수 있는 오류입니다. 사용자가 보고한 `connection.close()` traceback 및 앞서 브라우저에서 확인된 `GET /posts` 500과 일치할 가능성이 높습니다. 프론트엔드에는 로그인·회원가입·게시글 작성·상세 조회가 아직 백엔드에 연결되지 않은 상태이며, 새 개발 환경의 API 주소 예시도 현재 실행 주소와 다릅니다.

## 우선순위별 발견 사항

### P1 — SQLite 세션 정리 중 스레드 오류 가능성

- 근거: [`app/db/database.py`](../app/db/database.py)에서 `sqlite3.connect()`를 기본 설정으로 열고, `get_db()`가 연결을 yield한 뒤 `finally`에서 `connection.close()`를 호출합니다. 기본 `check_same_thread=True`인 SQLite 연결은 생성한 스레드와 다른 스레드에서 사용할 수 없습니다. FastAPI의 동기 의존성 생성기 정리 과정에서 스레드가 바뀌면 DB 사용 또는 연결 종료가 `sqlite3.ProgrammingError`로 실패할 수 있습니다.
- 영향: [`app/api/routers/posts.py`](../app/api/routers/posts.py)는 쿼리 중 `sqlite3.Error`를 500으로 변환합니다. 의존성 종료 시점의 오류는 앞선 DB 오류를 가릴 수도 있습니다.
- 추가 근거: 앞서 보고된 traceback의 마지막 애플리케이션 프레임이 `app/db/database.py`의 `connection.close()`였습니다. 이전 브라우저 점검에서도 `/posts`가 500을 반환했습니다. 이번 문서 작성 과정에서 런타임을 다시 호출해 재현하지는 않았습니다.
- 권고: 요청별 SQLite 연결을 유지하면서 `sqlite3.connect(DATABASE_PATH, check_same_thread=False)`를 사용하거나, 연결 생성·쿼리·종료가 반드시 같은 스레드에서 이뤄지도록 의존성 구조를 변경하세요. 적용 후 서버 로그의 최초 예외와 `/posts` 응답을 확인하세요.

### P1 — 로컬 로그인·회원가입 UI가 실제 인증 API를 호출하지 않음

- 근거: [`frontend/src/App.vue`](../frontend/src/App.vue)의 로그인·회원가입 폼 제출은 `submitUnavailable()`에 연결되어 있으며, 해당 함수는 기능이 백엔드에 연결되지 않았다는 안내만 표시합니다.
- 영향: 사용자는 폼을 제출해도 계정을 만들거나 로컬 계정으로 로그인할 수 없습니다.
- 권고: 로컬 인증을 제공할 계획이면 폼을 백엔드 엔드포인트에 연결하고, 아직 제공하지 않을 계획이면 입력 폼 대신 미지원 상태를 명확히 표시하세요.

### P1 — 게시글 작성 및 상세 화면이 API에 연결되지 않음

- 근거: `frontend/src/App.vue`의 게시글 작성 제출도 `submitUnavailable()`을 호출합니다. `/posts/:id` 화면은 상세 API 호출 없이 기능이 아직 없다는 고정 안내를 렌더링합니다.
- 영향: 목록에서 상세로 이동해도 게시글 내용을 볼 수 없고 새 게시글을 등록할 수 없습니다.
- 권고: 백엔드에 게시글 생성·상세 조회 API를 추가하고 프론트엔드에서 인증, 로딩, 오류, 존재하지 않는 게시글 상태를 처리하세요. API 경로와 응답 규약을 먼저 합의하는 것이 좋습니다.

### P2 — 프론트엔드 기본 API 주소와 실행 주소가 다름

- 근거: [`frontend/.env.example`](../frontend/.env.example)은 `VITE_API_BASE_URL=http://localhost:8000`을 안내합니다. 현재 로컬 `.env.local`은 8001을 사용하며, 이전 실행 시 8000 포트 bind 오류 때문에 FastAPI를 8001에서 실행했습니다. `App.vue`의 fallback도 8000입니다.
- 영향: 예시 설정으로 새 환경을 만들거나 환경 파일이 적용되지 않으면 프론트엔드가 잘못된 포트로 요청할 수 있습니다.
- 권고: 팀의 기본 백엔드 포트를 하나로 정한 뒤 `.env.example`, 프론트엔드 fallback, PyCharm/Uvicorn 실행 설정을 일치시키세요. 포트를 다르게 유지한다면 실행 방법과 환경 변수 설정을 개발 문서에 명시하세요.

### P2 — 로그아웃 요청 실패를 프론트엔드에서 구분하지 않음

- 근거: `frontend/src/App.vue`의 `logout()`은 `/auth/logout` 요청 결과를 확인하지 않고 로컬 프로필을 바로 지웁니다.
- 영향: 네트워크 오류나 서버 실패 시 HttpOnly 쿠키가 서버에서 폐기되지 않았는데 화면은 로그아웃된 것처럼 보일 수 있습니다.
- 권고: 응답 성공 여부를 확인한 뒤 프로필 상태를 갱신하고, 실패 시 사용자에게 오류와 재시도 방법을 안내하세요.

## 정상 구현으로 확인된 부분

- 카카오 로그인 버튼은 `startKakaoLogin()`을 호출하며, 콜백에서 인가 코드·state를 FastAPI의 `/auth/kakao/login`에 전달합니다.
- 프론트엔드 요청에 `credentials: 'include'`가 설정되어 있어 쿠키 기반 인증을 사용할 수 있습니다.
- 백엔드는 HTTP 오류, 요청 검증 오류, 미처리 예외를 `{code, message, result}` 형태로 감싸도록 구성되어 있습니다.
- 위 사항은 코드에서 확인한 것이며, 실제 카카오 개발자 콘솔 설정이나 외부 카카오 인증 성공까지 검증한 것은 아닙니다.

## 권장 처리 순서

1. SQLite 연결 스레드 설정을 정리하고 `/posts` 및 `/auth/me` 요청 오류를 확인합니다.
2. 기본 백엔드 포트를 통일하고 예시 환경 설정과 PyCharm 실행 설정을 맞춥니다.
3. 제품 범위에 따라 로컬 인증, 게시글 작성, 게시글 상세 API와 화면 연결 여부를 결정하고 구현합니다.
4. 로그아웃 실패 처리를 보강합니다.
