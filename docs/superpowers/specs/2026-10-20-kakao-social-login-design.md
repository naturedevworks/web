# 카카오 소셜 로그인 설계

## 목표와 범위

현재 프로젝트에는 게시글 목록 API만 있으며 사용자 계정, 인증 세션, 프런트엔드 로그인 연동은 구현되어 있지 않다. 이번 작업은 Vue 프런트엔드에서 카카오 로그인으로 사용자를 인증하고 FastAPI 백엔드에서 서비스 계정과 로그인 세션을 관리하는 기반을 추가한다.

이번 범위에는 카카오 로그인과 로그아웃, 현재 로그인 사용자 조회, 첫 소셜 인증 시 사용자 자동 생성이 포함된다. 구글 로그인은 제공자별 확장이 가능하도록 구조를 마련하되 이번 구현에서 제외한다. 게시글 API의 접근 제한, 글쓰기 기능, 이메일·비밀번호 가입, 계정 연결 UI는 포함하지 않는다.

## 승인된 접근 방식

Vue 프런트엔드는 카카오 JavaScript SDK를 초기화하고 `Kakao.Auth.authorize()`로 카카오 로그인을 시작한다. 프런트엔드 콜백 라우트가 인가 코드와 `state`를 받는다. 백엔드가 로그인 시작 시 `state`를 생성해 응답으로 반환하고 짧은 만료 시간의 HttpOnly 쿠키에도 설정한다. 프런트엔드는 `state`를 SDK 인가 요청에 포함한다. 콜백 후 프런트엔드는 인가 코드와 `state`를 백엔드 로그인 API로 전달하며, 백엔드는 요청의 `state`와 쿠키의 값을 비교해 검증하고 쿠키를 폐기한다.

백엔드는 카카오 인가 코드를 토큰으로 교환하고 카카오 사용자 정보 API를 호출한다. 카카오 토큰은 서버에서만 사용하고 저장하거나 프런트엔드에 전달하지 않는다. 서비스 프로필 정보로 카카오 닉네임만 요청·저장한다. 다만 반복 로그인에서 동일 카카오 계정을 찾기 위해 카카오가 응답하는 고유 사용자 ID도 제공자 식별자로 저장해야 한다. 서비스 세션은 충분한 엔트로피를 가진 불투명 토큰으로 만들고, 원문은 HttpOnly 쿠키에만 담으며 DB에는 해시만 저장한다.

## 대안 검토

1. **백엔드가 OAuth 리다이렉트와 콜백을 모두 처리:** 서버 경계가 단순하고 웹 리다이렉트와 잘 맞지만, 사용자가 선택한 프런트엔드 인증 결과 전달 방식과 다르다.
2. **Vue가 Kakao JavaScript SDK로 인증하고 인가 코드를 백엔드에 전달 (선택):** Vue 앱이 SDK 초기화, 콜백, 오류 화면을 제어할 수 있고 토큰 교환과 서비스 세션 발급은 백엔드에 둔다. CSRF 방지를 위해 `state`를 백엔드 발급 쿠키와 대조해야 한다.
3. **프런트엔드 SDK에서 받은 액세스 토큰을 백엔드에 전달:** 화면 통합은 직접적일 수 있으나 공급자 액세스 토큰이 프런트엔드에 노출되고, 인가 코드 서버 교환 흐름보다 토큰 경계가 분산된다.

선택안 2는 프런트엔드 콜백 제어를 제공하면서도 카카오 토큰 및 서비스 세션 발급을 서버에 유지한다.

## API 계약 초안

모든 API는 기존 프로젝트의 응답 봉투 `{ code, message, result }` 형식을 따른다. Vite 개발 프록시는 `/api` 접두사를 제거하므로 프런트엔드 경로는 `/api/auth/...`, FastAPI 경로는 `/auth/...`로 구성한다.

### `GET /auth/kakao/state`

- 로그인 시작용 무작위 `state`를 생성해 JSON 결과에 반환한다.
- 동일 값의 짧은 수명 HttpOnly 쿠키를 설정한다. `SameSite=Lax`를 적용하고, HTTPS 환경에서는 `Secure`를 적용한다.
- Vue는 카카오 JavaScript 키로 SDK를 초기화한 뒤 반환된 `state`와 등록된 콜백 URI를 `Kakao.Auth.authorize()`에 전달한다.
- 카카오 개발자 콘솔에 등록한 JavaScript SDK 도메인과 콜백 URI가 필요하며, 인증 요청의 `redirectUri`는 등록 값과 일치해야 한다.

### `POST /auth/kakao/login`

- 요청: `{ "code": "...", "state": "..." }`
- 서버가 쿠키와 요청 본문의 `state`를 비교하고 유효한 인가 코드를 카카오 토큰 API로 교환한다. 인가 코드 요청과 같은 `redirect_uri`를 토큰 교환에 사용한다.
- 카카오 사용자 프로필에서 닉네임과 안정적인 카카오 사용자 ID만 사용한다. 이메일 scope를 요청하지 않는다.
- 성공 시 서비스 세션 쿠키를 설정하고 공개 가능한 사용자 프로필만 결과에 반환한다.
- 누락되거나 잘못된 입력은 422, state 불일치·만료된 로그인 시도는 400/401, 카카오 인증 거부·토큰 교환·프로필 조회 실패는 적절한 4xx/502 응답을 사용한다. 공급자 토큰과 비밀 정보는 응답이나 로그에 포함하지 않는다.

### `GET /auth/me`

- 세션 쿠키를 확인해 로그인된 서비스 사용자 요약을 반환한다.
- 세션이 없거나 만료되었으면 401을 반환한다.

### `POST /auth/logout`

- 현재 세션을 폐기하고 쿠키를 만료시킨다. 이미 로그아웃된 경우도 안전하게 처리한다.

## 저장 구조와 계정 정책

- `users`: 내부 사용자 ID, 표시 이름, 생성 시각 등 서비스 계정 필드.
- `oauth_accounts`: 사용자 ID, 제공자(`kakao`), 제공자 사용자 ID, 생성 시각. `(provider, provider_user_id)` 고유 제약 조건을 둔다. 이메일은 요청하거나 저장하지 않는다.
- `sessions`: 사용자 ID, 세션 토큰 해시, 만료 시각, 생성 시각. 토큰 해시를 고유하게 저장한다.

첫 카카오 인증 시 사용자와 제공자 계정을 자동 생성한다. 로그인 이름은 카카오 프로필 닉네임을 사용한다. 닉네임이 없으면 가입을 거부하고 사용자에게 카카오 프로필 정보 제공 설정을 안내한다. 카카오 이메일은 요청하거나 저장하지 않는다. 계정 식별은 이메일이 아닌 `(provider, provider_user_id)`로 한다. 따라서 카카오 이메일과 로컬 계정 이메일의 동일 여부를 확인해 거절하는 규칙은 이메일을 받지 않는 현재 정책으로는 구현할 수 없다.

## 프런트엔드 흐름

1. 앱 초기화 시 설정된 JavaScript 키로 Kakao JavaScript SDK를 초기화한다. 키가 없으면 카카오 로그인 동작을 명확한 설정 오류로 표시한다.
2. 로그인 화면에서 카카오 로그인 버튼을 누르면 `/api/auth/kakao/state`를 호출한다.
3. `Kakao.Auth.authorize()`에 등록된 `redirectUri`와 응답의 `state`를 전달해 인증을 시작한다.
4. 콜백 라우트에서 `code`, `state`, 또는 카카오가 반환한 오류를 읽는다.
5. 성공이면 `POST /api/auth/kakao/login`을 호출한다. 실패·취소이면 사용자에게 재시도 가능한 상태를 보여 준다.
6. 성공하면 로그인 상태를 갱신하고 게시글 화면으로 이동한다. 새로고침 후에는 `/api/auth/me`로 로그인 상태를 복구한다.
7. 로그아웃 시 `/api/auth/logout` 호출 후 화면 상태를 비운다.

브라우저 요청은 쿠키를 포함해야 한다. 현재 Vite `/api` 프록시를 통해 개발 환경에서도 같은 출처 경로를 유지한다.

## 설정과 오류 처리

카카오 JavaScript 키와 REST API 키, 클라이언트 시크릿, SDK 인가 요청 및 토큰 교환에 동일하게 사용할 리다이렉트 URI, 프런트엔드 성공 후 이동 경로는 환경 설정으로 관리한다. 비밀 값은 저장소에 커밋하지 않는다. 설정이 빠진 경우 애플리케이션 시작 또는 로그인 요청에서 명확한 서버 오류로 처리한다.

사용자 취소, 만료되거나 잘못된 인가 코드, 네트워크 오류, 동의하지 않은 프로필 항목은 사용자에게 재시도 또는 안내 메시지를 보여 주고 서버에 토큰·인가 코드·클라이언트 시크릿을 기록하지 않는다. 공급자 세부 오류는 기존 응답 봉투에서 안전한 메시지로 변환한다.

## 검증 계획

프로젝트의 최상위 `AGENTS.md`는 검증하지 않고 넘어가라고 지시하므로 테스트 실행은 계획에서 제외한다. 구현 시에는 테스트 파일을 추가하지 않는다. 변경한 API 계약과 설정을 문서화하고, 코드 검증 없이 완료를 주장하지 않는다.
